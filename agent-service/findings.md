# Agent Service Findings

## 2026-07-30 - Phase 5–6 completion evidence

- OpenAI-compatible requests are now protocol-tested exclusively with `httpx.MockTransport`: text, one/two function calls, invalid tool name/arguments, non-JSON/empty/invalid completion shape, 429/5xx retry, timeout, streaming chunks, interrupted stream, cancellation, and user-token redaction before model context.
- Provider construction and readiness remain network-silent. Only explicit `openai_compatible` configuration requires key/base URL/model; development/test fallback is explicit and warning-bearing, while production rejects silent fallback.
- The Agent now applies a final provider-context minimization boundary, process-local IP/concurrency/SSE limits, and bounded in-memory conversation TTL/capacity cleanup. Limits have safe 429 errors and release request/tool/model/SSE slots in `finally` paths.
- The 50-case deterministic/Fake Backend evaluation produced 100% for auth gate, safety block, hallucination-free registered-tool use, maximum-tool compliance, and response shape. Intent and tool-selection coverage both reported 98% because two deliberately ambiguous/no-identifier cases are not forced into a tool call.
- Final offline Agent verification: `compileall app` passed; `pytest -m "not real_backend"` passed `60`, deselected `3`, with only the pre-existing non-fatal unwritable `.pytest_cache` warning. `python -m evals.runner` passed all 50 cases. No real model, 8090, 5174, public network, MySQL, Redis, or OSS access occurred.
- Vue production build passed with 1755 modules transformed. Existing Rollup PURE-comment and large-chunk warnings remain; no frontend unit-test framework was present, so no dependency was introduced.

## 2026-07-30 - Phase 5–6 implementation baseline

- The existing Agent already separates the three intended providers at configuration time and keeps the default Mock combination offline. The OpenAI-compatible adapter is currently minimal: it creates a network client only during calls, but lacks protocol-level streaming/cancellation/health behavior, strict finish/tool validation, injectable fake transport, and explicit fallback semantics.
- Orchestration already uses the registered tool whitelist, Pydantic validation, a two-tool setting, and request-scoped Authorization handling. It currently needs explicit limiter ownership, session TTL/capacity cleanup, provider-safe result minimization, and safe handling for an unavailable personal tool before model-driven selection.
- The Vue user stack keeps the ordinary token in `qh:token` and admin token in a separate utility. `http.js` chooses the token by `/admin/` path and clears only the matching session on HTTP 401. The assistant integration must call the Agent base URL directly with only `getToken()`, never reuse the admin utility or create a second authentication system.
- The existing `UserLayout.vue` owns normal-user logout. It is the appropriate narrow hook for clearing only the assistant `conversation_id` from `sessionStorage` after logout, while the new `/assistant` route remains publicly reachable for public read-only questions.

## 2026-07-30 - Phase 4.5 scope restoration

- The only permitted repair surface is `agent-service/`. The approved order is: diagnose the existing virtual environment and process environment, prefer explicit `.venv` interpreter invocation, add Agent-local process-isolation helpers if needed, and create a new local virtual environment only if contamination is demonstrated and a non-Anaconda CPython exists.
- Real integration must use `AGENT_MOCK_MODE=false`, `AGENT_TOOL_MODE=spring`, `QINGHE_BACKEND_ENABLED=true`, `QINGHE_BACKEND_BASE_URL=http://127.0.0.1:8090`, `LLM_PROVIDER=deterministic`, and an empty `LLM_API_KEY`. This configuration is process-local or ignored-local only; no model request is allowed.
- The existing `.venv` is not a clean CPython environment: its `pyvenv.cfg` identifies Anaconda as home, its Python reports Anaconda packaging, and `sys.path` resolves standard-library modules through the Anaconda base. `ctypes` cannot load its `_ctypes` extension (access denied), which blocks Click, Uvicorn, and therefore FastAPI startup. Process-local PATH cleanup cannot correct this base-interpreter contamination; the next safe option is a fresh local venv based on a verified non-Anaconda CPython.
- `CONDA_PREFIX`, `CONDA_DEFAULT_ENV`, and `CONDA_PROMPT_MODIFIER` are unset, although the invoking shell PATH includes Anaconda entries. A local CPython 3.12.0 outside Anaconda imports `ctypes` successfully. A replacement `.venv-clean` was therefore created from that interpreter and received only this project’s declared packages, leaving the old `.venv` in place.
- The prior registry exposed the shop-goods endpoint only to direct real-backend checks, not as an Agent tool, and the deterministic provider had no distinct intent for currently available coupons. Phase 4.5 now adds typed, public-only `get_shop_goods` and `get_active_coupons` paths. Neither accepts identity fields; goods output is limited to public product summary fields and states no product-level promotion inference.
- The clean virtual environment successfully imports `ctypes`, Click, FastAPI, and Uvicorn, and runs the offline suite. Its `ctypes` originates from the independent CPython installation, not Anaconda. The old `.pytest_cache` is not writable in this execution context; pytest reported it as a warning only and completed all 42 selected offline tests.
- The user-operated Spring Boot service is reachable at 127.0.0.1:8090. The explicitly enabled real suite passed its public read-only and FastAPI-ASGI public/error checks. Its only skipped case is the guarded personal-success test because no `QINGHE_TEST_USER_TOKEN` exists; this did not cause credential discovery or substitution.
- Real 8100 Socket evidence now proves the complete public path rather than a direct-Spring substitute: the 15-tool deterministic Spring service handled promotions, active coupons, shop search/detail/goods, hot explore posts, and nearby shops. It also safely rejected no-Token personal access, a fixed invalid Token, an unavailable shop ID, invalid longitude, and invalid radius. No output contained Token-like credentials, the 8090 internal URL, or Python/Java stack text.
- The real SSE check proved `text/event-stream`, required normal-event order, a structured `error` event for injection blocking, Chinese UTF-8 payloads, and a healthy subsequent request after an intentionally closed client stream. The temporary Uvicorn process was stopped by its verified 8100 owner PID and the port was released.
- The only remaining evidence gaps are intentionally non-destructive: normal-user personal success/authorization scenarios await a user-supplied Token; real temporary-backend-unavailable, definite empty-data, and business-failure cases need a naturally occurring safe state because this phase cannot stop Spring or alter business data.

## 2026-07-31 — Phase 8 source audit (middleware, token and provider baseline)

- Existing HTTP handling is one FastAPI function middleware in `app/main.py`: it assigns request context/ID, applies chat IP admission and request-body limits, adds an access log, and maps `AgentError`; CORS is FastAPI `CORSMiddleware`. This has the requested responsibilities but not independently named/testable ASGI components.
- Existing pipeline safeguards are already valuable and must be reused: regex safety/intent classification, `ToolRegistry` auth gate and Pydantic validation, fixed maximum two tool calls, per-tool timeout/concurrency slot, provider-context sensitive-key cleanup, and final safe user error mapping. `AgentOrchestrator.handle` currently owns nearly all of these stages, which is the primary coupling point.
- Token controls currently consist only of message/body length, provider `max_tokens`, a ten-turn conversation cap, and OpenAI payload construction. There is no input estimate, context-window accounting, system/history/schema/tool-result allocation, session total, actual usage capture or cost calculation. OpenAI payloads currently receive the full `registry.metadata()` list in each `select_tools` call.
- Conversation retention stores raw recent user messages plus 240-character answer summaries and tool names. It excludes request context and raw results, but requires Phase 8 sanitization and a deterministic rolling summary so user-provided Token-like text and personal details cannot persist.
- Provider retry is embedded in `OpenAICompatibleProvider._complete`; fallback is an explicit development-only wrapper. There is no circuit breaker, profile registry/router, structured route decision or provider usage capture. The existing production validator already rejects silent fallback and remains the policy baseline.
- `InMemoryMetrics` records only intent counts and total tool calls. Structured logs exclude simple secret fields, but no usage/cost aggregate endpoint or OTel-like spans currently exists. The `AgentGraph` is only a stable custom-state-machine facade, not a graph runtime; no checkpoint/recovery requirement has been found that justifies LangGraph.

## 2026-07-31 — Phase 8 implementation evidence

- `TokenBudgetManager` allocates pre/post input, reserved output, system/history/Schema/result budgets using an explicit conservative estimator. Provider usage overrides estimates only when supplied; otherwise it remains `estimated=true`. Conversation clear removes cumulative budget state.
- `ToolSchemaSelector` hides all tools for greeting/help/safety/unsupported and caps relevant candidates at four. `AgentOrchestrator` retains its existing hard execution cap of two. Public cache keys contain only normalized public-tool arguments; authentication-required tools get no key.
- The profile router is logical and locally safe: deterministic 17, fast 28 and standard 5 benchmark decisions across the existing 50 local cases. There is no real model invocation, price, exporter, Redis cache or LangGraph migration.
- Final benchmark is real local output: average estimated input 4372.86 to 318.62; P50 4373 to 220; P95 4376 to 647; Schema 1954.00 to 176.96; history 1855.00 to 119.00; result 565.00 to 23.00; reduction 92.71%; avoided model calls 21.

## 2026-07-30 - Phase 4 initial audit

- The default configuration is fully offline: `agent_mock_mode=true`, `agent_tool_mode=mock`, `llm_provider=mock`, and `qinghe_backend_enabled=false`.
- Current settings reject `AGENT_MOCK_MODE=true` with Spring tools and permit only `mock` or `openai_compatible` providers. The provider factory likewise omits the existing deterministic provider. This prevents the requested `deterministic + spring` combination and must be corrected in Agent code only, while preserving Mock defaults.
- `agent-service/.gitignore` currently excludes `.env` but not `.env.local` or `.env.*.local`; Phase 4 must add the requested private-local exclusions and may create an example file containing only placeholders.
- Actual contract re-audit confirmed public coupon/shop/explore paths, seven current-user paths, the `Result(code,message,data)` envelope, default page/size values, and the `PageResult(records,total,page,size)` shape directly from Controller/DTO/VO source.
- Actual public Stage A calls proved all six required GET routes reachable at 8090 with HTTP 200 and business code 200. The Actuator route is absent (HTTP 404), so public GET is the approved availability evidence.
- The real dorm VO uses `campusName`, `buildingName`, `roomNo`, `bedNo`, and `checkInStatus`; public coupon stock uses `availableStock`. Agent adapters now minimize these and other VO outputs before a deterministic response is formed.
- A temporary FastAPI socket process cannot currently start because Uvicorn's Click import resolves Anaconda `ctypes` and fails DLL access. This is a local runtime blocker, not a safe reason to alter system settings or dependencies.
