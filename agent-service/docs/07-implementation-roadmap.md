# 青禾校园智能助手：分阶段实施路线图

本路线图是后续授权的实施建议，不代表本阶段开始编码。每个 Phase 完成后必须更新项目记录、如实记录验证，并等待用户确认后才进入下一阶段。

| Phase | 开发目标与修改范围 | 验收标准 | 测试方法 | 依赖条件与主要风险 |
|---|---|---|---|---|
| 0：审计 | 完成现有项目、接口、身份和数据缺口审计；仅 `agent-service/docs` | 八份设计文档一致，未改业务代码/数据 | 文件清单、链接、术语和禁止项静态核对 | 风险：历史文档过时；以源码为准。 |
| 1：基础骨架 | 新建 FastAPI 目录、health、settings、Provider 抽象、HTTPX Client、错误/日志框架；无业务写工具 | `/health` 可用；环境变量无真实 Key；Client 白名单与错误码就绪 | pytest 单测、配置缺失/超时测试 | 需用户批准 Python 版本与依赖；风险：模型供应商/SDK 变化。 |
| 2：公共只读工具 | 商铺、商品浏览、可领取券、附近商铺、热门探店工具和编排 | 仅调用用户端 GET；工具输出符合 schema；公共查询可匿名 | MockTransport 集成、参数边界、回退/限流测试 | 风险：商品搜索与促销数据缺口，先标为不可用。 |
| 3：登录用户只读工具 | 当前资料、宿舍、我的券、订单、默认地址工具 | Bearer 透传；无 userId 参数；401/403 一致 | Token 透传、横向越权、脱敏、订单归属测试 | 风险：个人信息暴露，需日志脱敏和真实测试环境。 |
| 4：RAG 知识问答 | 文档清洗、版本/来源元数据、嵌入、检索、引用和过期策略 | 静态知识可追溯；不把实时事实进向量库 | 检索相关性、旧版本/注入、无资料降级评测 | 需确认正式规章和资料授权；风险：过期或错误语料。 |
| 5：Vue3 接入 | 用户聊天入口、SSE 渲染、会话/错误态、隐私提示；不改管理员入口 | 用户 Token 正确传给 Agent；401 回到用户登录；无管理员 Token | 前端单测/构建、浏览器手工验收、SSE 中断恢复 | 需用户批准前端改造；风险：跨域、流式断连、坐标隐私。 |
| 6：评测、安全与可观测性 | 评测集、指标、trace、限流、熔断、注入/越权防护、告警 | 评测基线可复现；安全对抗通过；依赖不可用可解释 | pytest、集成、安全、回归、人工红队 | 风险：模型幻觉与后端抖动；必须有无工具拒答机制。 |
| 7：受控写操作 | 单独设计订单/券等写工具的预览、确认、幂等、审计和取消语义 | 每次写操作有可读预览、二次确认、后端重检和审计 | 幂等、过期确认、并发、权限、回滚测试 | 风险最高；不得由模型直接写业务数据。 |

## Phase 1--3 的最小测试集合

- Pydantic schema：额外字段、空值、ID、分页、经纬度、半径、长度与枚举。
- Spring Boot Client：Bearer 原样透传、路径白名单、管理员路径拒绝、超时分类、一次重试、业务码映射。
- 工具：每个工具的成功、空结果、401、403、404、超时、不可用和脱敏输出。
- 编排：工具选择白名单、最多调用次数、重复调用阻断、没有事实时不编造。

## Phase 4--6 的评测门槛

评测集中至少覆盖本文件矩阵的十类意图、错误/模糊问题、不可用依赖、Prompt 注入、管理员诱导、伪造 userId、跨订单 ID、宿舍/地址敏感信息、坐标拒绝与旧知识。记录正确工具选择率、工具结果忠实度、拒答正确率、越权拦截率、敏感泄露率、P95 工具/模型时延和错误率；未达门槛不得扩大到写操作。
