# 青禾校园智能助手：Spring Boot API 与数据缺口分析

## 可直接复用的只读接口

| Agent 能力 | 复用接口 | 结论 |
|---|---|---|
| 当前资料 | `GET /api/user/me` | 可用，身份由当前 Token 决定。 |
| 商铺搜索/详情/店内商品 | `GET /api/shops`、`GET /api/shops/{id}`、`GET /api/shops/{id}/goods` | 可用，商铺列表已有 keyword。 |
| 商品浏览/详情 | `GET /api/goods`、`GET /api/goods/{id}` | 可用作浏览，不适合关键词搜索或促销判断。 |
| 今日可领取券 | `GET /api/coupons` | 可用；当前服务端以领取窗口和库存判定。 |
| 我的券 | `GET /api/coupons/mine` | 可用；天然当前用户范围。 |
| 我的订单及详情 | `GET /api/orders`、`GET /api/orders/{id}` | 可用；已做当前用户归属校验。 |
| 我的宿舍 | `GET /api/student/dorm/me` | 可用；已做当前用户范围和脱敏。 |
| 默认地址 | `GET /api/addresses` | 可用但需 Agent 在已授权的当前用户列表内筛选。 |
| 附近商铺 | `GET /api/explore/shops/nearby` | 可用；经纬度和半径均已有校验。 |
| 热门探店 | `GET /api/explore/posts?sort=hot` | 可用；无独立 endpoint 并非能力缺口。 |

## 必须新增或调整的用户端只读能力

| 优先级 | 缺口 | 推荐最小改造 | 原因与验收点 |
|---:|---|---|---|
| P0 | 商品关键词搜索 | 扩展 `GET /api/goods?keyword=` 或新增 `GET /api/goods/search`；仅搜索上架商品和正常营业店铺 | 支撑 `search_goods`；关键词长度/分页受控，不能调用管理员商品查询。 |
| P0 | 商品直接优惠 | 先由业务确认模型：原价、活动价、活动起止、状态、适用范围；再新增只读 `GET /api/promotions/goods` | 没有真实字段就不能回答“正在打折”。 |
| P1 | 今日优惠统一视图 | 新增只读 `GET /api/promotions/today`，聚合券与未来已确认活动，返回服务端时间、来源类型和适用范围 | 当前券接口可用，但不应把“券”误称为所有优惠活动。 |
| P1 | 店铺优惠筛选 | 为券列表增加受控 `shopId` 或新增 `GET /api/shops/{id}/promotions` | 避免 Agent 通过大页数下载后在内存猜测。 |
| P1 | 我的券的店铺名称 | `UserCouponVO` 可补 `shopName`，或由后端专用视图批量装配 | 避免模型把 ID 猜成店名。 |
| P2 | 默认地址专用读取 | `GET /api/addresses/default`，只返回当前用户默认地址且默认脱敏 | 减少传输无关地址、降低个人信息暴露面。 |
| P2 | Agent 合同稳定性 | 为每个供 Agent 调用的 GET 端点建立版本化 OpenAPI/契约测试 | 防止 VO 字段或业务码变化导致工具静默失效。 |

## 不应新增为普通用户 Agent 数据源的接口

- 不得暴露任意用户、学生、入住记录、订单或优惠券查询端点。
- 不得复用 `/api/admin/**` 数据作为普通用户工具的数据源。
- 不得为了 Agent 新增“按 userId 查询我的数据”的接口；必须使用当前 Token 解析身份。
- 不得把 MySQL、Redis、后台报表、密钥或管理配置直连给 FastAPI。

## “今日优惠”与“优惠商品”的可信口径

| 问题 | 当前结论 | 可安全回答方式 |
|---|---|---|
| 今天有哪些优惠券 | 可靠：领取时间窗、库存、启用状态在当前服务实现中实时判断 | “当前可领取的优惠券”并列出领取/使用窗口与店铺范围。 |
| 哪些商铺最近有优惠 | 部分：券含 `shopId`，但未返回店铺名，且“最近”没有明确时间定义 | 先显示“有当前可领取券的店铺 ID/需补店名”；最好新增聚合接口。 |
| 哪些商品正在优惠 | 不可靠：缺少原价、促销价、促销窗和商品适用关系 | 明确说明暂无商品级促销数据，不生成推荐事实。 |
| 哪些商品可用优惠券 | 不可靠：仅能确认店铺级券，无法证明商品级排除/适用规则 | 在新增后端适用性计算接口前，不回答为确定事实。 |

## 建议的后端验收契约

新增只读接口必须：从 `UserContext` 解析个人身份；拒绝客户端 userId；使用分页/上限；统一 `Result` 与业务错误码；不泄露后台字段；覆盖未登录、过期 Token、越权、空结果、边界时间、库存变化和并发状态变更。所有 SQL 仅在用户审核后人工执行，本阶段不生成或执行迁移。
